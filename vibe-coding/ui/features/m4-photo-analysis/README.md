# M4 照片分析 畫面

- 確認日期：2026-11-21
- 依據規格：[M4 規格](../../../specs/2026-11-21-m4-photo-analysis.md)
- 開啟方式：瀏覽器打開 `index.html`。上半部「流程試玩」可以操作；工具列切換淺色／深色、手機／桌機、模擬分析結果、今天剩餘次數。下半部「畫面一覽」是每個狀態的靜態畫面。
- demo 的「現在」固定為 19:42，上傳的範例照片拍攝於 12:31，用來看出兩種入口的預設餐別不同。

## 定案設計（demo 確認，2026-11-21）

- ＋選單把「拍照」「上傳照片」做成兩格，點了直接進入（不採用「一格拍照分析再展開兩個選項」）；桌機只有「上傳照片」。
- 「看不出食物」時，重試同一張沒有意義，主按鈕改成「重拍／換一張」。
- 飲食頁的餐點卡在時間旁標「照片」，表示由照片分析建立（依 `meals.source = ai`）。
- 信心度分級：高 ≥ 0.75、中 ≥ 0.5、低 < 0.5；以三格訊號＋文字顯示，「低」用橘色並在展開時提醒。

## 畫面情境

- m4-01/quick_add：＋選單「拍照」「上傳照片」各一格；桌機不顯示「拍照」
- m4-02/analyze_camera：分析頁（拍照），照片下方標「現在 19:42」，可重拍；補充說明選填（200 字）；顯示今天剩餘次數
- m4-03/analyze_upload：分析頁（上傳），標「拍攝於 今天 12:31」，可換一張
- m4-04/analyzing：分析中，照片掃描動畫、補充說明鎖定、可取消（已送出仍算一次）
- m4-05/error_retry：Gemini 忙碌／逾時／其他錯誤，「重新分析」用同一張照片，或「改手動輸入」
- m4-06/error_not_food：看不出食物，「重拍／換一張」或「改手動輸入」
- m4-07/limit_reached：今天次數用完，只能改手動輸入
- m4-08/confirm：確認分析結果，沿用新增餐點表單；上方摘要（縮圖、辨識出 N 個項目、補充說明）；項目帶信心度；時間依拍攝時間帶入的提示
- m4-09/leave_confirm：確認頁按返回，詢問是否放棄這次分析
- m4-10/meals_after_save：存檔後回飲食頁，toast「已新增午餐」，餐點卡標「照片」
- m4-11/desktop_quick_add：桌機＋選單只有「上傳照片」
- m4-12/desktop_analyze：桌機分析頁，左照片、右補充說明與按鈕
- m4-13/desktop_confirm：桌機確認頁，兩欄
